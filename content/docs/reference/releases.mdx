These guides use the following published releases:

| Component            | Version | Distribution                             |
| -------------------- | ------- | ---------------------------------------- |
| CLI                  | 0.17.8  | `npm install --global ingestron@0.17.8`  |
| Core                 | 0.12.14 | Included as an exact CLI dependency.     |
| Local provider       | 0.4.6   | `ingestron provider install local`       |
| ADF provider         | 4.7.0   | `ingestron provider install adf`         |
| Databricks provider  | 3.7.0   | `ingestron provider install databricks`  |
| Files connector      | 1.4.0   | `ingestron connector install files`      |
| SQL Server connector | 1.4.0   | `ingestron connector install sql-server` |
| PostgreSQL connector | 1.0.0   | `ingestron connector install postgresql` |
| MySQL connector      | 1.0.0   | `ingestron connector install mysql`      |
| Oracle connector     | 1.0.0   | `ingestron connector install oracle`     |
| Stripe connector     | 0.1.0   | `ingestron connector install stripe`     |
| SharePoint connector | 0.1.0   | `ingestron connector install sharepoint` |
| OneDrive connector   | 0.1.0   | `ingestron connector install onedrive`   |
| Azure Blob connector | 2.0.0   | `ingestron connector install azure-blob` |
| GitHub connector     | 1.35.0  | `ingestron connector install github`     |

With CLI 0.17.8, an official name without a version selects exactly these
releases, because they are the ones qualified for core 0.12.14. Add `@<version>`
to reproduce a tutorial exactly. Older CLIs keep selecting the releases qualified
for their own core version.

The CLI and core require Node 22.12 or newer. CI covers Node 22.12, 22.23 and 24.12.
Local execution is qualified on macOS/Linux with Python 3.12. A wider Node engine
range is not a claim that every future Node release has been tested.

## What is included

Project and contract authoring, provider and connector installation, builds, local files, Azure Blob, SQL Server, PostgreSQL, MySQL, Oracle, Stripe, SharePoint, OneDrive and GitHub snapshot
execution, output verification, retry and the local stdio MCP adapter are documented
here. The original code is Apache-2.0, licensed by Otrera Limited. Upstream
components retain their own licence terms.

Native ADF/Databricks execution, scheduling and hosted enterprise services are not
offered by these guides. The local GitHub procedure is a preview:
automated tests use synthetic API responses, and a bounded anonymous live run against
the public Ingestron CLI repository has passed. Neither establishes throughput or
independent-user acceptance.

## Updating

Upgrade the CLI with an explicit version, then check `ingestron --version`. Review
package updates separately using [plugin installation](/docs/guides/plugins).
Keep your project lock in Git. Do not assume that updating the CLI also changes a
project's provider or connector selection.

Core 0.12.14 adds [bridges](/docs/concepts/sources#bridges): ADF lands a
source that Databricks cannot reach, a Databricks job publishes each snapshot and
Lakeflow applies it, all from one flow; `check` shows the bridge as one route and
suggests it when a native route is billed separately. `check` also works on
projects combining ADF and Databricks flows. ADF 4.7.0 reads Salesforce and
HubSpot natively; Databricks 3.7.0 reads Salesforce, HubSpot and Jira through
Lakeflow Connect. Stripe, SharePoint and OneDrive 0.1.0 are portable preview
connectors tested against mocks of the vendors' documented APIs. Local provider
0.4.6 names each connector's error code.

Core 0.12.13 adds [source routes](/docs/concepts/sources): a connection can be
read by a portable connector or natively by ADF or Databricks, and `check` shows
each route's licence, cost, access and maturity. ADF 4.6.0 and Databricks 3.6.0
add native routes for SQL Server, PostgreSQL, MySQL, Oracle, object storage and
SharePoint; their generated assets are checked offline, not run on a real
platform. Every connector now uses the same layout: the connection holds the
endpoint and credentials, each table names one object, and the contract selects
columns and types. Azure Blob 2.0.0 moves to that layout (a breaking change for
1.x projects, which keep working on 1.x). PostgreSQL, MySQL and Oracle 1.0.0 pass
the shared connector test suite against real servers in local containers.

Files 1.3.0, SQL Server 1.3.0, Azure Blob 1.2.0 and GitHub 1.34.0 check
[contract quality rules](/docs/concepts/contracts#quality-rules) before each
snapshot is committed. Their installed runs, with CLI 0.17.4 and local provider
0.4.4, include a duplicate key that stops the run with nothing committed and a
warning that is recorded in the receipt. These releases need core 0.12.10 or
newer.

Files 1.2.0 reads several contracted local files through one connection and
carries reviewed source-to-target field names into the output. Its ten-file
installed run checked discovery, review and all five formats with CLI 0.17.0,
core 0.12.7 and local provider 0.4.3. The [retail training exercise](/docs/tutorials/retail-files)
uses Files 1.2.0 and tests all five formats. Older Files 1.0.1 and 1.1.0
downloads remain available under their original releases. See
[file settings and limits](/docs/reference/files).

Azure Blob 1.1.0 reads individual objects using read-only SAS credentials and the
local provider. Its installed run covered all five formats with CLI 0.17.0. See the
[Azure retail exercise](/docs/tutorials/azure-blob).

GitHub 1.33.1 reads GitHub.com issues. Its installed run covered pagination,
review, retry and tamper rejection against synthetic API responses with CLI 0.17.0.

SQL Server 1.2.0 selects multiple contracted tables through one connection and is
qualified for core 0.12.7 with synthetic data. SQL password was live-qualified on
an earlier one-table release with read-only Northwind; live multi-table and Entra
identity tests remain pending. See [SQL Server settings and limits](/docs/reference/sql-server).
