---
title: "Read Azure Blob and ADLS Gen2 files"
description: "Use one storage connection to read several contracted blobs with the local provider."
---

Azure Blob connector 2.0.0 reads CSV, TSV, JSON, JSONL or Parquet blobs into
reviewed Parquet snapshots. One connection names the storage account, container
and SAS; each table in an ingestion flow names one blob and its format, and its
ODCS data contract selects the columns and types. The local provider runs on
your machine, so it must be able to reach the account. Start with the
[Azure retail exercise](/docs/tutorials/azure-blob).

```sh
ingestron provider install local@0.4.5
ingestron connector install azure-blob@2.0.0
```

```yaml
connections:
  retail_blob:
    package: azure-blob
    sourceId: retail
    tenantId: training
    settings:
      account: yourstorageaccount
      container: samples
      sas_token:
        $secret:
          env: AZURE_STORAGE_SAS
flows:
  - apiVersion: ingestron.flow/v1
    kind: ingestion
    id: retail_local
    provider: local
    ingestion:
      connection: retail_blob
      execution: { mode: local }
    tables:
      customers:
        source: { path: retail/v1/csv/customers.csv, format: csv }
        contract: { $resolve: ./contracts/customers.odcs.yaml }
```

| Connection setting | Value                                                       |
| ------------------ | ----------------------------------------------------------- |
| `account`          | Azure public-cloud storage account name, not a URL          |
| `container`        | Blob container or ADLS Gen2 file system name                |
| `sas_token`        | Secret reference: `{ $secret: { env: AZURE_STORAGE_SAS } }` |

| Table `source` key | Value                                                  |
| ------------------ | ------------------------------------------------------ |
| `path`             | Exact blob path inside the container, no leading slash |
| `format`           | `csv`, `tsv`, `json`, `jsonl` or `parquet`             |

Types come from each table's contract, as for [local files](/docs/reference/files);
there is no `types` map. Azure Blob 1.x kept one blob, its format and `types` in
each connection; those releases and the 1.1.0 exercise download remain
available and are not changed by installing 2.0.0.

Use a time-limited HTTPS-only SAS with read or read/list permission. Plaintext tokens
in project configuration, account keys and ambient Azure login are unsupported.
Tokens must contain explicit permissions and expiry; stored-policy-only SAS tokens
are not supported. Credentials are resolved only in the local runtime.

The connector checks size and ETag before downloading each blob and uses a
conditional read. It rejects redirects, incomplete downloads and blobs that
change during the read. Every selected blob is read before any record is
committed, so a failure in a later table commits nothing. Discovery and
execution are separate reads, so data may change between them if its schema
still matches the approved contract.

The [file format limits](/docs/reference/files) apply, including 64 MiB and one million
rows per blob. This release has no directory scans, wildcards, incremental sync,
version pinning, managed identity, custom endpoints or sovereign-cloud support.
ADLS Gen2 files use the Blob endpoint. Your machine still needs network access
allowed by the account's firewall or private endpoint. For managed identity or
private networks, see [native routes](/docs/concepts/sources).

The connector is a preview: it is tested with CLI 0.17.7, core 0.12.13 and a
loopback Azure fixture across all five formats, not against a live storage
account.
