A pack turns definitions into the files for one platform: its methods ingest,
transform or store a table. Each pack has a page of its methods, settings and
defaults, rendered from the pack itself.

## Available packs

| Pack                                                              | Responsibilities                                         | Generated output                                                   |
| ----------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------ |
| [Databricks](/docs/reference/packs/databricks) (`databricks@1`)   | Supported direct ingestion, transforms and storage       | Bundles, pipelines, SQL or Python files, and jobs where configured |
| [Azure Data Factory](/docs/reference/packs/adf) (`adf@1`)         | Native copying from supported sources to landing storage | Linked services, datasets, pipelines and triggers                  |
| [Synapse serverless](/docs/reference/packs/synapse) (`synapse@1`) | SQL views over landed files and transforms               | `views.sql` for the serverless database                            |
| [DuckDB](/docs/reference/packs/duckdb) (`duckdb@1`)               | Tables, transforms and local runs, published as Parquet  | `run.sql` and each table's SQL                                     |

Connector-specific access and ingestion requirements are in
[Connections](/docs/connectors).

These four packs come with the command and the editor. Adding another name to
`packs` does not install a provider plugin. Do not assume a combination that no
route offers works.
