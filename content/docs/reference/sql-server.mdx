---
title: "Read SQL Server tables"
description: "Use one database connection to read several contracted tables."
---

SQL Server connector 1.1.0 reads selected SQL Server or Azure SQL tables into
reviewed Parquet snapshots. The local provider runs on your machine, so it must
be able to reach the database. Use an identity with `SELECT` access to the tables
and permission to view their column metadata.

Install the provider and connector in your project directory:

```sh
ingestron provider install local@0.4.1
ingestron connector install sql-server@1.1.0
```

Put the exact installed package names in `packages`. One connection holds the
database endpoint and authentication. Each table in an ingestion flow names its
physical schema and table; its ODCS data contract selects the columns:

```yaml
packages:
  local: local@0.4.1
  sql-server: sql-server@1.1.0
connections:
  northwind:
    package: sql-server
    sourceId: northwind
    tenantId: training
    settings:
      connection:
        server: example.database.windows.net
        database: northwind
        authentication:
          method: sql-password
          username: reader
          password:
            $secret:
              env: SQL_READER_PASSWORD
flows:
  - apiVersion: ingestron.flow/v1
    kind: ingestion
    id: northwind_local
    provider: local
    ingestion:
      connection: northwind
      execution: { mode: local }
    tables:
      products:
        source: { schema: dbo, table: Products }
        contract: { $resolve: ./contracts/products.odcs.yaml }
      orders:
        source: { schema: dbo, table: Orders }
        contract: { $resolve: ./contracts/orders.odcs.yaml }
```

This is a section of `project.yaml`; the
[complete one-table project template](https://github.com/ingestron/connectors/blob/sql-server-1.1.0/examples/sql-server/project.template.yaml)
also includes the provider configuration, environment and an inline draft
contract. To add a second table, add another `tables` entry and contract under
the same flow. You can also use `contract: {$model: pack:dataset}` to select a
reviewed contract from an installed model pack.

The contract is the column list for that table. There is no separate
`object.columns` setting. Changing a connection, table source or contract
requires a new build and review. The short package names resolve through
`packages.lock.yaml`, which retains the full repository reference, commit and
file hashes. Older stream-based projects keep working with their pinned
connector release.

Save `SQL_READER_PASSWORD` in your local environment or a project `.env` file.
Pass that file with `ingestron run --secrets-file .env`. Do not put the password
in YAML. See [secrets](/docs/guides/secrets).

| Authentication method     | Add these settings                            | Identity source                       |
| ------------------------- | --------------------------------------------- | ------------------------------------- |
| `sql-password`            | `username`, `password` secret reference       | SQL login                             |
| `entra-default`           | None                                          | Local Azure Identity credential chain |
| `entra-managed-identity`  | Optional `client_id`                          | Identity assigned to Azure compute    |
| `entra-service-principal` | `client_id`, `client_secret` secret reference | Entra application                     |

SQL password has passed a read-only run against the existing Northwind Azure SQL
database using the previous one-table release. The multi-table release has
passed synthetic runtime and installed-package build checks; a live multi-table
read is still pending. The Entra modes have passed configuration tests, but
still need a live database identity test. ADF linked services and Databricks
native connections require separate provider implementations.

After editing the project, run `ingestron check`, `ingestron build` and
`ingestron runtime prepare`. Then [discover, review, approve and run](/docs/guides/runs)
the flow. An approved retry verifies existing output without reading SQL again.

The local reader scans at most one million rows per table in batches and caps
each record at 2 MB. It supports integer, boolean, decimal/money, floating,
text, identifier and date/time columns; dates and times become ISO text. Review
money fields as exact `DECIMAL(19,4)` in the contract. Unsupported selected
columns fail discovery. Output field names must use letters, digits and
underscores, starting with a letter or underscore.

Discovery and execution are separate reads. The connector checks schema drift
but does not promise an ordered or transactionally consistent snapshot while
rows are changing. TLS and certificate validation are required; raw connection
strings and certificate bypass are unavailable. The adapter installs a pinned
Microsoft Python driver and ODBC binary with separate upstream terms. See the
[source package and full limits](https://github.com/ingestron/connectors/blob/sql-server-1.1.0/docs/sql-server.md).
