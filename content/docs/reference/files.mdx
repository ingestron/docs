---
title: "Read local files"
description: "Read several files through one connection and use each table's contract for types."
---

Files connector 1.1.0 reads CSV, TSV, flat JSON, JSON Lines and Parquet through
local provider 0.4.1. One connection can serve several files. Each table in the
ingestion flow names its file and format; its ODCS data contract selects the
columns and types for the reviewed Parquet snapshot.

Install the provider and connector in your project directory:

```sh
ingestron provider install local@0.4.1
ingestron connector install files@1.1.0
```

This is the relevant part of a two-file `project.yaml`:

```yaml
packages:
  local: local@0.4.1
  files: files@1.1.0
connections:
  local_files:
    package: files
    sourceId: retail
    tenantId: training
    settings: {}
flows:
  - apiVersion: ingestron.flow/v1
    kind: ingestion
    id: retail_files_local
    provider: local
    ingestion:
      connection: local_files
      execution: { mode: local }
    tables:
      customers:
        source: { path: /absolute/data/customers.csv, format: csv }
        contract: { $resolve: ./contracts/customers.odcs.yaml }
      orders:
        source: { path: /absolute/data/orders.csv, format: csv }
        contract: { $resolve: ./contracts/orders.odcs.yaml }
```

The [complete two-file template](https://github.com/ingestron/connectors/blob/files-1.1.0/examples/files/project.template.yaml)
includes provider configuration, an environment and draft contracts. Replace its
absolute path placeholders before checking it. You can also keep one file per
flow when they need different run schedules; the flows can share the connection.

The connection has no local endpoint or credentials. A table's `source.path` must
be an absolute regular file path. Directories, URLs, glob patterns, symlinks and
traversal segments are rejected. Choose `csv`, `tsv`, `json`, `jsonl` or `parquet`
for `source.format`. Changing a file path, format or contract requires a new
build and review. See [project runs](/docs/guides/runs).

Files 1.1.0 has no separate `types` map. It derives parsing types from the ODCS
columns: string, integer, decimal, number and boolean are supported. The
contract may select a subset of a file's columns. DATE, TIMESTAMP and BINARY
columns are not supported by this reader. CSV and TSV require a header. Empty
JSON or JSONL uses the reviewed contract columns as its schema.

Discovery checks every selected file. Extraction checks for source schema changes
and validates all files before publishing records, so a failure in a later file
cannot commit part of the flow. A new run ID reads current values; a completed
retry verifies existing output without rereading the files.

Each input is capped at 64 MiB and one million rows, with at most 500 columns and
2 MB per output record. These are preview bounds, not measured throughput. The
reader needs enough local disk for input, temporary spool and output. See the
[connector guide](https://github.com/ingestron/connectors/blob/files-1.1.0/docs/files.md)
for format rules and limits.

The [retail tutorial](/docs/tutorials/retail-files) uses Files 1.1.0 to write
one connection and three contracted tables by hand. The older Files 1.0.1
exercise remains available in its original release; installation does not
rewrite an older project. For storage objects, use
[Azure Blob](/docs/reference/azure-blob).
