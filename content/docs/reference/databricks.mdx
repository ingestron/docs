---
title: "Databricks provider"
description: "Native Databricks asset generation with provider-databricks 3.7.0."
---

The Databricks provider turns a reviewed project into a Databricks Asset Bundle
you deploy with your own tooling. It generates files only: it does not deploy, run
jobs or connect to your workspace or data. Install it with:

```sh
ingestron provider install databricks@3.7.0
```

| Standard                      | What it generates                                                 |
| ----------------------------- | ----------------------------------------------------------------- |
| `snapshot-with-history@v1`    | Complete versioned snapshots to native history and a current view |
| `change-feed-with-history@v1` | Baseline and full-row change events to history and a current view |
| `append-only@v1`              | Immutable files to a streaming table                              |
| `snapshot-publication@v1`     | Verify immutable Parquet snapshots, then publish a delivery index |
| `query-ingestion@v1`          | Database tables through Lakeflow Connect query-based connectors   |
| `sharepoint-ingestion@v1`     | SharePoint files and lists through Lakeflow Connect               |
| `saas-ingestion@v1`           | Salesforce, HubSpot and Jira through Lakeflow Connect             |

## Native source routes

A connection with `route: native` is read through a Unity Catalog connection
named in the environment binding (see [sources and routes](/docs/concepts/sources)).
Lakeflow Connect managed connectors run on serverless compute and are billed
separately; `check` shows this before you choose them.

| Source kind                                   | Standard                  | Status                       |
| --------------------------------------------- | ------------------------- | ---------------------------- |
| `sql-server`, `postgresql`, `mysql`, `oracle` | `query-ingestion@v1`      | Preview, billed separately   |
| `azure-blob`, `s3`, `gcs`                     | Auto Loader standards     | Included in pipeline compute |
| `sharepoint`                                  | `sharepoint-ingestion@v1` | Preview, billed separately   |
| `salesforce`                                  | `saas-ingestion@v1`       | GA, billed separately        |
| `hubspot`                                     | `saas-ingestion@v1`       | GA; CRM tables Beta          |
| `jira`                                        | `saas-ingestion@v1`       | Beta                         |

SaaS tables read only the reviewed contract columns. When a private source is
only reachable from ADF, use a [bridge](/docs/concepts/sources#bridges).

Output includes `databricks.yml`, job and pipeline resources, notebooks and
targets per environment. Secrets stay as secret-scope references. Generated
YAML, Python and SQL files start with a note that they are generated and should
not be edited.

## Contract quality rules

[Contract quality rules](/docs/concepts/contracts#quality-rules) become native
checks. Rules never drop rows.

| Standard                                        | Checks                                                                                                                                                   |
| ----------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `append-only@v1`, `change-feed-with-history@v1` | Column rules with `mustBe: 0` become Lakeflow expectations. `severity: error` fails the update; other rules keep the row and record expectation metrics. |
| `snapshot-with-history@v1`                      | Every library rule is counted on the delivered snapshot. An error rule stops the update before the snapshot is applied.                                  |

On streaming standards, other thresholds fail the build, and `duplicateValues`
and `rowCount` rules are reported as not enforced.

`type: sql` rules run on complete snapshots through `spark.sql`, where `${table}`
is the delivered snapshot. On streaming standards they are reported as not
enforced. `type: custom` rules with `engine: databricks` take a Spark SQL row
condition as `implementation`, for example `amount >= 0`; they become
expectations on streaming tables and are counted on snapshots. Rules for other
engines are reported as not enforced.

Generation is tested offline against synthetic projects with CLI 0.17.8 and core
0.12.14. Deployment and execution on a real Databricks workspace are not qualified by
this release. Source, guides and examples:
[ingestron/provider-databricks](https://github.com/ingestron/provider-databricks).
