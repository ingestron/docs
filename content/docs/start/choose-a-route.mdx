A route is the path your data takes from its source to where it is kept. It
decides which packs the project uses: a pack is the part of Ingestron that
writes one platform's files. Project creation, in the CLI and in
VS Code, offers only the routes your source supports; `--via` names one on the
command line.

## Choose a route

Under each route is the list of packs its standard uses.
[Packs and methods](/docs/reference/packs) has each pack's methods.

<RouteTable detail />

ADF feeds Synapse views and DuckDB tables only when it copies tables, not when
it copies files as they are. Microsoft 365 data lands as JSON, so it has no
Synapse route. ADF works for sources on a public endpoint or reachable from the
workspace, as well as private ones. On the `adf-databricks` route, Databricks
reads the landed files; it does not open a second connection to the source.

These routes are all Ingestron generates for. Naming another platform in the
YAML does not add one.

## Reachability

A connection says how its source can be reached with `connectivity`. Each
ingestion method says which values it supports, and Ingestron uses them to
check or choose a method. It does not create network routes or test the
connection.

| Value       | Meaning in the current connector catalogue                                  |
| ----------- | --------------------------------------------------------------------------- |
| `public`    | The source is reachable through a public endpoint                           |
| `workspace` | The source is reachable from the workspace used by the ingestion method     |
| `private`   | The source requires an ingestion runtime with access to its private network |

Reachability describes the source's access path only. It is separate from
where the data is kept, and from the editor or command you use. Each
connector's page gives its exact runtime and authentication requirements.

Project creation offers the routes that support both the connector and its
reachability, and a standard can limit them further. A method chosen by hand
that cannot read the source is reported as a problem. For example, SQL Server
on `public` or `workspace` can use Databricks directly (Lakeflow Connect) or
any ADF route; on `private`, only the ADF routes:

## Create it

<ToolSteps>
<Tool name="CLI">

```sh
ingestron init sales --connector sqlserver --connectivity private --via adf-databricks
```

Without `--yes`, `init` asks for each choice the flags leave out, and, in a
terminal, last, which assistant files to write. It writes
`REPLACE_ME` for each value it cannot know, such as the server, and its
`README.md` lists them. Add `--standard <path or Git URL>` to use your organisation's
standard. For DuckDB on a laptop, use `--template duckdb` instead, as in
[Run your first project on your laptop](/docs/start/first-project).

</Tool>
<Tool name="VS Code">

Run **Ingestron: New project** and choose **From a connection**. Pick the
source, its reachability and a route; the list shows only the routes that
support both.

</Tool>
</ToolSteps>

[Create a project](/docs/how-to/start-from-a-template) covers
every option. Generating the files and deploying them stay separate steps.
