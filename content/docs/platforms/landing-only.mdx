When reports read the files ADF lands, for example Power BI reading Parquet
files from storage, ADF can be the whole project. Each flow ends at the files
ADF lands, and nothing loads them into tables.

<RouteFacts id="adf-landing" />

## What Ingestron writes [#what-you-get]

For each environment, the ADF pack writes the factory's resources: linked
services for the source, the Key Vault and the landing storage, a dataset for
each side of the copy, a pipeline and its trigger.

## Settings that shape it [#settings]

<OldAnchor id="end-flows-at-the-landed-files" />

`store: { default: none }` ends every flow at the landed files. To end one flow
there, write `store: { uses: none }` in that flow. When nothing chooses a store,
`ingestron plan` reports it, and the editor offers both changes as fixes. The
runtime, Key Vault, landing storage and schedule are set as on
[Azure Data Factory](/docs/platforms/adf#runtime-and-key-vault).

### Choose how the files are laid out

Set the layout in the standard, under the method's settings:

| Setting                                                    | Files                                                                       |
| ---------------------------------------------------------- | --------------------------------------------------------------------------- |
| `layout: snapshot`                                         | One file per table, `<object>/<object>.parquet`, replaced by each load      |
| `layout: increments`                                       | A new file per load in `<object>/`, named by the window's start and the run |
| `path: "{object}/{yyyy}/{MM}/{dd}/{object}_{run}.parquet"` | A path of your own under the landing folder                                 |

Reports that read the current data need `snapshot`: the file's path never
changes, so a report keeps working after each load.

<Screenshot
  src="/images/platforms/landing-only/storage-02-customers-file.png"
  label="Azure portal"
  checked="2026-11-02"
  alt="The northwind.dbo.Customers folder holds one file, northwind.dbo.Customers.parquet."
  caption="With layout: snapshot, the demo's landing/northwind/northwind.dbo.Customers folder holds one file, which each load replaces."
/>

A path must include `{object}`, so each table keeps its own files. Its other
tokens are `{connection}`, the window's start `{yyyy}`, `{MM}`, `{dd}` and
`{HH}`, and `{run}`. A path adds a file per load when it has `{run}` or the date
tokens down to the window's unit, such as `{HH}` for hourly loads; otherwise
each load replaces the file.

Without a setting, a flow that ends at the landed files gets `snapshot`. When
each load holds only its window's rows (`mode: incremental`, or a Microsoft 365
dataset's date filter), it gets `increments` instead, so no rows are lost.
Ingestron refuses a layout that would lose rows: loads holding only their
window, written to a file the next load replaces. Every value is in the
[`layout`](/docs/reference/packs/adf#adf-copy-layout) and
[`path`](/docs/reference/packs/adf#adf-copy-path) reference.

## Deploy [#deploy]

<OldAnchor id="generate-and-publish" />

Run `ingestron apply`. With only the ADF pack, each environment's folder under
`build/` holds the `linkedService`, `dataset`, `pipeline` and `trigger` folders
directly. Bring them into your factory as described in
[Publish the factory](/docs/platforms/adf#publish).

## Run and operate [#operate]

Once published, the trigger copies every table each window, and each load
replaces its file. Outside production the trigger is stopped, as the
[platform defaults](/docs/reference/packs/adf#platform-configuration) say:
start it in Data Factory, or set `paused: false` for the copy method in the
platform, when you want the copies to run. Point reports at the snapshot paths, such as
`<landing>/erp.dbo.Customers/erp.dbo.Customers.parquet`.

When a copy fails or a trigger does not run, see
[Azure Data Factory](/docs/troubleshooting#azure-data-factory) in
Troubleshooting.

## Limits [#limits]

<OldAnchor id="what-is-not-checked" />

- **No rows are checked.** Nothing reads the files before your reports do, so
  each contract quality rule and flow expectation on these tables is reported
  as not checked (`QUALITY_RULE_NOT_CHECKED`); see
  [Check data quality](/docs/how-to/add-quality-checks).
- **No transforms.** A transform cannot read a table that ends at the landed
  files: give its flow a store step first.
