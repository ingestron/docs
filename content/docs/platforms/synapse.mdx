---
title: Synapse serverless views
description: Show the files ADF lands to reports as Synapse serverless SQL views, with transforms as views too.
---

When reports need SQL tables, but nothing should run or be stored after each
load, Synapse serverless SQL can show the files ADF lands as views. A transform
becomes a view over other views, and Synapse reads the files each time a report
queries a view.

## Settings that shape it [#settings]

<OldAnchor id="list-synapse-first-and-keep-tables-as-views" />
<OldAnchor id="name-the-external-data-source" />
<OldAnchor id="write-a-transform-as-a-view" />

`store: { default: synapse-view }` keeps every table as a view over the files
ADF lands. The database is named by the standard's `naming.catalog`, here the
Synapse pack's default, `{{ project }}_{{ environment }}`; see
[Name tables and resources](/docs/how-to/name-things-your-way).

`data_source` and `data_source_location` name the external data source in
every view, and every file a view reads must be under the location:

<SettingsSections
  pack="synapse"
  method="synapse-view"
  include={["data_source", "data_source_location"]}
/>

`layout: snapshot` lands one file per table, so each view shows the current
data; a view over files that each load adds shows every load's rows. ADF's
schedule, runtime and landing settings are on
[Azure Data Factory](/docs/platforms/adf#runtime-and-key-vault). What a view's
SQL can do is in
[What each engine makes of it](/docs/how-to/write-a-transform#what-each-engine-makes-of-it).

### Views or tables

A view cannot merge changes or keep history. For that, keep the table with a
store pack and serve it with `synapse-serve`; see
[Keep a table current](/docs/how-to/keep-a-table-current#on-synapse).

|                             | Views (Synapse)                              | Tables (a store pack, served with `synapse-serve`) |
| --------------------------- | -------------------------------------------- | -------------------------------------------------- |
| Runs after each load        | Nothing                                      | The store pack's job                               |
| Cost                        | Data scanned each time a report reads a view | The job's run time, plus data scanned when read    |
| Merge, history              | No: the files as they are                    | Yes                                                |
| Heavy joins over large data | Recomputed on every read                     | Computed once per load                             |

## Deploy [#deploy]

<OldAnchor id="generate-then-run-the-views" />

Run `ingestron apply`. Each environment's folder holds the ADF resources under
`adf/` and the views in `synapse/views.sql`. Publish the factory's resources as
in [Publish the factory](/docs/platforms/adf#publish).

Then run `views.sql` against the environment's serverless database, here
`sales_dev`, with Synapse Studio, a CI step or the Go version of `sqlcmd`,
signed in with `az login`:

```sh
sqlcmd -S <workspace>-ondemand.sql.azuresynapse.net -d sales_dev \
  --authentication-method ActiveDirectoryDefault -b -i build/dev/synapse/views.sql
```

Replace `<workspace>` with your Synapse workspace's name. `-b` stops at the
first error. See
[Authenticate with Microsoft Entra ID in sqlcmd](https://learn.microsoft.com/en-us/sql/tools/sqlcmd/sqlcmd-authentication)
for the other ways to sign in (checked 5 November 2026).

## Run and operate [#operate]

Loads need nothing more: ADF replaces the files on its schedule, and each query
reads the files as they are then. Run `views.sql` again whenever the
definitions change, such as a new table or column. It creates or alters every
view, so running it again is safe; it drops nothing, so a view for a table you
removed stays until you drop it.

When a view fails to create or to read its files, see
[Synapse serverless views](/docs/troubleshooting#synapse-serverless-views) in
Troubleshooting.

## Limits [#limits]

- **No rows are checked.** A view checks no rows, so the contract's quality
  rules and required columns are reported as not checked
  (`CONTRACT_FIELD_UNUSED` warnings); see
  [Check data quality](/docs/how-to/add-quality-checks).
- **No merge or history.** A view shows the files as they are; see
  [Views or tables](#views-or-tables).
