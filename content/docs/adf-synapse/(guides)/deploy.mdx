---
title: Deploy both
description: Deploy each environment's factory, then run its Synapse views script, by hand or from CI.
---

Ingestron writes the factory and the views script and deploys neither. Deploy
each environment's factory first, then run its views script: a view reads the
files the factory lands.

## Before you deploy [#prerequisites]

`ingestron request --env dev` lists what both need, with this project's
values: the integration runtime, Key Vault and landing storage for the factory,
then the serverless database, the external data source and the report users
for the views. Each platform's page says more about its part:
[the factory](/docs/adf/deploy#prerequisites) and
[the views](/docs/synapse/deploy#prerequisites).

## Deploy [#deploy]

1. Run `ingestron apply`.
2. Build the factory's ARM template once and deploy it with the environment's
   parameter file, as in
   [Build the template and deploy it](/docs/adf/deploy#build-and-deploy).
3. Run the environment's views script with sqlcmd (Go), from
   `build/synapse`, signed in with `az login`, as in
   [Deploy to Synapse](/docs/synapse/deploy#deploy):

   ```sh
   cd build/synapse
   sqlcmd -S <workspace>-ondemand.sql.azuresynapse.net --authentication-method ActiveDirectoryDefault -i environments/dev.sql
   ```

   Replace `<workspace>` with your Synapse workspace's name.

Loads need nothing more: the factory replaces the files on its schedule, and
each query reads the files as they are then. Run the views script again
whenever the definitions change.

### From CI [#deploy-from-ci]

Each environment's stage in the CI templates deploys the factory, then runs
the views script, in that order. Each platform's page gives its steps:
[the factory](/docs/adf/deploy#deploy-from-ci) and
[the views](/docs/synapse/deploy#deploy-from-ci).
