---
title: Which setting wins
description: Where a method's settings come from, and which one wins.
---

Each method has settings, such as the file format or the clustering. A
setting can be written in several places. Later places win:

1. the pack's default for the method;
2. the standard's `<action>.settings.<method>`;
3. the platform's `settings.<method>`;
4. the `with` of the rule that chose the method, if any;
5. the flow's or transform's `<action>.with`;
6. the table's own `<action>.with`.

The standard's `<action>.fixed.<method>` settings come last. A flow,
transform or table that sets one to a different value is an error
([`FIXED_SETTING`](/docs/reference/errors#FIXED_SETTING)), not silently
overridden. When a fixed setting is a mapping, only the keys it names are
fixed. If the standard fixes `properties: { acme: { owner: data-platform } }`,
a flow may still add `properties: { team: { cost_centre: "123" } }`, but not
change `acme.owner`.

For a step-by-step policy example, follow
[Set your organisation's standard](/docs/how-to/configure-a-standard).

Every result is checked against the method's settings, so a misspelt or
missing setting is reported with the file and line where it was written
([`BAD_SETTING`](/docs/reference/errors#BAD_SETTING)). Each method's
settings and defaults are in [Reference: packs and methods](/docs/reference/packs).

## Intent

[Intent](/docs/reference/intent), such as `history` or `audit`, has an order
of its own: the standard, then the table's layer, a `load.when` rule, the flow
or transform, and the table, with the standard's `fixed` intent last. What is
still unset comes from the chosen method's own default. See
[Which value wins](/docs/reference/intent#precedence).

Some settings are other names for intent, such as `streaming-table`'s
`mode: upsert`, which is `history: latest`. Written as a setting, one still
works, in the place it is written, and `plan` says
[`SETTING_MOVED`](/docs/reference/errors#SETTING_MOVED), with a fix that
writes the intent instead; see
[Settings that are intent](/docs/reference/intent#settings-that-are-intent).

## Names, layers, types and quality

These are not method settings, and `fixed` does not apply to them. For each,
a later place wins:

- **Names:** the pack's default patterns, the standard's `naming`, then the
  platform's `naming`.
- **Layers:** the pack's default list, then the standard's `layers`. A flow or
  transform picks one of them with `layer`.
- **Types:** the pack's type for each logical type, the standard's `types`,
  then a column's `physicalType`.
- **Quality:** the pack's default actions, the standard's `quality`, then an
  expectation's `action`.

The pack is the standard's first pack. A name pattern in the platform
document replaces the standard's pattern for that name, and the standard's
`types` change only the logical types they list. See
[Name tables and resources](/docs/how-to/name-things-your-way),
[Layers](/docs/concepts/layers) and
[Give each column a type](/docs/how-to/write-a-contract#give-each-column-a-type).
