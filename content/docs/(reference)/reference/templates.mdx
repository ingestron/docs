A template is a project folder with a `template.yaml`. `ingestron init` copies
the folder into a new project, writes its `README.md`, and asks nothing. A
starter is a template that ships with Ingestron: a complete project for one
common situation, with `REPLACE_ME` where you write your own values. See [Share templates and standards](/docs/how-to/share-a-template)
to make a template of your own.

## Create a project from a starter [#create-a-project-from-a-starter]

In the CLI, name the starter with `--template`. The new `README.md` lists each
value still `REPLACE_ME`; `--set` writes them as the project is created:

```sh
ingestron init my-project --template retail --yes
```

In VS Code, **Ingestron: New project** then **From a starter** lists the same
starters by title and name. Either way, the result is ordinary definitions you
edit; [Create a project](/docs/how-to/start-from-a-template#start-from-a-starter)
covers folders and Git URLs, and `--standard` and `--set`. To start from a
source instead of a starter, see
[Start from a connection](/docs/how-to/start-from-a-template#start-from-a-connection).

## `template.yaml`

| Field       | Required | Meaning                                                                  |
| ----------- | -------- | ------------------------------------------------------------------------ |
| `title`     | yes      | The template's human-readable title                                      |
| `summary`   | yes      | One sentence on what the template sets up                                |
| `questions` | no       | Values for `project.yaml`, each written to `values.<value>`; never asked |

Each question:

| Field     | Meaning                                                               |
| --------- | --------------------------------------------------------------------- |
| `value`   | The key in `project.yaml` `values`: lowercase letters, digits and `_` |
| `ask`     | What the value is                                                     |
| `default` | The value written, unless `--set <value>=<text>` gives another        |

The built-in starters have no questions: they write `REPLACE_ME`, with a
comment, where a value is yours to give.

Any other field is an error, so a misspelt one is found at once. Your editor
checks `template.yaml` too after `ingestron schemas`.

## Files

`init` copies the template folder's files, apart from `template.yaml`,
`README.md`, `build`, `.generated.json`, `.git` and `.ingestron`. A file
named `gitignore`, in any folder, is written as `.gitignore`, because npm does
not always publish files whose names start with a dot. A template shared as a
folder or Git URL can hold either name.

## Download a starter [#download-a-starter]

Downloads come without generated files: run `ingestron apply` in the folder
to write them. Each is what `ingestron init <name> --template <name> --yes`
writes: the starter's definitions, with `REPLACE_ME` where a value is yours
to give, and the `README.md` that lists each one and where to find it. `plan`
and `apply` warn about each `REPLACE_ME`, and `check` fails until each is
written. The platforms and connectors listed are read from the resolved
starter.
