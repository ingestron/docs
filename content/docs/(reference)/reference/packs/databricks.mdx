`databricks@2` writes one Databricks bundle for every environment, with a
target per environment: Lakeflow pipelines with SQL and Python files,
Lakeflow Connect ingestion, and a refresh job when the platform has a schedule
or a task runs after the refresh. See
[What Ingestron writes](/docs/platforms/databricks#what-you-get).
The settings below come from the pack itself.

Before deployment, [plan and review](/docs/how-to/plan-and-generate) the files,
then [deploy the generated bundle](/docs/platforms/databricks-deploy#deploy).

## Platform configuration

Without a platform document, or where it leaves a setting out, the Databricks
pack uses these defaults. Each target of the bundle gets its environment's
`mode`, workspace, `run_as` and `permissions`, from the platform's
`databricks:` section. Without `run_as`, the pipelines and jobs run as the
identity that deploys the bundle, and without `schedule`, nothing runs on a
schedule.

`schedule`, `tags` and `alerts` stay at the top of the platform, where every
pack that runs jobs reads them. Only enable management of shared resources
when this project owns them. The following capability reference describes
each switch and its prerequisites.

### The `databricks:` section [#platform]

What only Databricks reads goes in the platform's `databricks:` section. Each
field says where to find its value, and what it could look like; the editor's
hover says the same.

<PlatformSection pack="databricks" />

Written at the top of the platform, as before 2.3, `workspace`, `mode`,
`run_as`, `compute`, `permissions`, `manage` and `grants` still work, with a
[`PLATFORM_FIELD_MOVED`](/docs/reference/errors#PLATFORM_FIELD_MOVED) warning
whose fix moves each into the section. `notifications.on_failure` becomes an
email alert in `alerts`.

## Platform prerequisites

Some features change shared Unity Catalog objects, so the platform turns each
on with a `databricks.manage` switch. While a switch is off, a definition or contract that
uses the feature gets a `CAPABILITY_OFF` warning with a quick fix that turns it
on. When a switch is on, the bundle has a `prerequisites/<environment>.sql` for
each environment, which lists the grants to run once there as an
administrator; it is not deployed.

Tags, column comments and table checks run in an `apply_contract` task after
the refresh, on serverless jobs compute: Lakeflow pipelines cannot set tags or
column comments, nor compare counts over all rows. With no schedule, the job
is still generated, to run on demand.

## Intent [#intent]

What this pack does with each value of [intent](/docs/reference/intent), from
the pack itself. A value the pack does not apply, **Not yet** or **Not
applicable**, is a [`NOT_APPLIED`](/docs/reference/errors#NOT_APPLIED) warning
where it is written, with the reason below. **Elsewhere** values are applied by
another pack or step and never warn. **Release** is the Databricks feature's
own release level, as the linked page said on the date checked; with
`features: ga`, a feature in preview is a
[`PREVIEW_FEATURE`](/docs/reference/errors#PREVIEW_FEATURE) warning.
