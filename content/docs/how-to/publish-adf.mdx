---
title: Publish ADF resources
description: Review generated copy resources and publish them through your factory's Git workflow.
---

Use this after [planning and generating](/docs/how-to/plan-and-generate) a project
with the ADF pack. With ADF alone (the `adf-landing` route), its output is
`build/<environment>/`; when the standard lists another pack too, it is
`build/<environment>/adf/`. Ingestron generates files; it does not publish the
factory or provision the runtime, source access, Key Vault or landing storage.

## Review the generated resources

Inspect the `linkedService`, `dataset`, `pipeline` and `trigger` directories.
Confirm names, credential references, landing paths, schedules and paused state
for the intended environment. Prepare the [shared infrastructure](/docs/how-to/adf-runtime)
and the connector-specific access requirements before running the pipelines.

Keep generation ownership files in the Ingestron output folder; the ADF resource
JSON is the content to bring into the factory's configured Git root.

## Use the factory's publishing workflow

Bring the reviewed resources into a feature branch of the factory repository,
then review and merge them into its collaboration branch. In ADF, publish from
that collaboration branch. Committing to Git alone does not update the live
factory. Publishing includes the factory's changes, so review the complete
pending set with the factory owner.

Follow Microsoft's [source-control and publishing instructions](https://learn.microsoft.com/en-us/azure/data-factory/source-control#publish-code-changes)
for the factory's configured Git integration and permissions. For an automated
release pipeline, use the organisation's established ADF deployment process.

## Deploy downstream resources separately

When the standard lists another pack, its files are a separate output beside
`adf/`, and publishing the factory does not deploy or schedule them:

- `build/<environment>/databricks/`: follow
  [Deploy the Databricks bundle](/docs/how-to/deploy-the-bundle).
- `build/<environment>/synapse/`: run its `views.sql`, as in
  [Synapse serverless views](/docs/platforms/synapse).
- `build/<environment>/duckdb/`: follow [Run DuckDB in Azure](/docs/platforms/duckdb-in-azure).
