---
title: Keep a table current
description: Keep the current row for each key, or every version, from loads of changed rows on DuckDB or Databricks.
---

Use this when each load brings rows that change rows the table already has:
a key, a column that orders the changes, and sometimes a column that says
which rows are deletions. The store method's `mode` decides what the table
keeps. Set it in the flow's `store.with` for every table of the flow, or in a
table's own `store.with` for that table alone. These modes need the contract to
mark the key with `primaryKey: true`; see
[Describe a table with a contract](/docs/how-to/write-a-contract#keys-and-required-columns).

| Engine     | Current row per key | Every version | Deleted keys  |
| ---------- | ------------------- | ------------- | ------------- |
| DuckDB     | `upsert`            | No            | No            |
| Databricks | `upsert`            | `history`     | `delete_when` |
| Synapse    | No                  | No            | No            |

## On DuckDB

`duckdb-table` replaces the table with the files' rows each run, unless the
table sets another `mode`. In the [DuckDB starter](/docs/start/first-project),
this keeps one row per order, the latest by `ordered_at`:

```yaml
# flows/orders.yaml
tables:
  orders:
    object: orders.csv
    contract: shop.orders
    store: { with: { mode: upsert, sequence_by: ordered_at } }
```

<SettingsSections pack="duckdb" method="duckdb-table" include={["mode", "sequence_by"]} />

Each run then inserts each key's latest row, by `sequence_by` and then by file
name, and replaces the row the table had for that key. Set `sequence_by` when
one file can hold a key twice. Running again is safe in every mode. A changed
primary key or column type needs the table built again: delete
`ingestron.duckdb` and run again, which reloads everything from the files.
Every setting is listed under
[`duckdb-table`](/docs/reference/packs/duckdb#duckdb-table).

## On Synapse

A Synapse view reads the landed files each time a report queries it, so it
shows them as they are: it cannot merge changes or keep history. To keep
current rows, keep the table with DuckDB, whose tables are published as files,
and serve it with `synapse-serve`; see [Views or tables](/docs/platforms/synapse#views-or-tables).

## When ADF lands the rows

ADF copies the rows; the pack that stores the table keeps it current. A
native table copy lands the whole selection each window, so a row missing
from a later copy does not mean it was deleted. See
[Choose the source and its tables](/docs/platforms/adf#choose-the-source-and-its-tables).
