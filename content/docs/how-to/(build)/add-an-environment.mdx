<Tool name="VS Code">

To see the new environment's problems and previews, click the environment in the status bar, or run **Ingestron: Select environment**, and choose `test`.

</Tool>

The new environment gets no folder of its own. It joins the files each
platform already has: here, a `test` target in the bundle's `databricks.yml`,
with the values that differ between environments:

<Example name="environments" file="build/databricks/databricks.yml" pick="targets.test" />

Other platforms add their own file or folder for it; see
[Where the files go](/docs/concepts/generated-files#where-the-files-go).

Only an environment named `dev` is in development mode; every other one,
`test` included, is in production mode, and schedules run only in `prod` or
`production`, so `test`'s refresh job is paused. A platform can set
`databricks.mode` and `schedule.paused` itself; see the
[platform defaults](/docs/reference/packs/databricks#platform-configuration).
Environments may differ only in values, such as names, paths and hosts: a table
built in one environment only is refused as
[`ENVIRONMENTS_DIFFER`](/docs/reference/errors#ENVIRONMENTS_DIFFER).

To deploy the new environment, add it to your deployment pipeline as
[Deploy through environments](/docs/how-to/deploy-through-environments#add-an-environment)
shows.

## Check what differs

Before deploying, see what the new environment changes compared with one you
know:

```sh
ingestron compare --env dev --env test
```

For the example above, it prints:

```text
# dev ↔ test: finance

## Platform

- `mode`: `development` → `production`
- `workspace.root_path`: `/Workspace/Shared/.bundle/finance/dev` → `/Workspace/Shared/.bundle/finance/test`
- `tags.environment`: `dev` → `test`
- `sections.databricks.workspace.root_path`: `/Workspace/Shared/.bundle/finance/dev` → `/Workspace/Shared/.bundle/finance/test`

## Table journals

- `full name`: `finance_dev.bronze.journals` → `finance_test.bronze.journals`
- `ingest.connection.settings.path`: `/Volumes/dev_landing/finance/files/ledger` → `/Volumes/test_landing/finance/files/ledger`
```

`compare` resolves both environments first, with every value and default in
place, and lists only what differs:

- **Platform:** the platform document's values, and the defaults that follow
  from the environment, such as `mode`. The values of a pack's own section,
  such as `databricks:`, show twice: as the pack reads them, such as
  `workspace.root_path`, and as written, under `sections.databricks`. Compared with `prod`, it also shows
  `schedule.paused`, because only `prod` runs its schedule.
- **Names:** the pipeline and job names, which are not per table.
- **Table:** one section for each table that differs: its full name, each
  step's method and settings, the connection's settings and the table's
  checks.

A value one environment has and the other lacks shows as `not set`. A
`${secret:…}` reference shows as `a secret`, never its value. Without `--env`,
`compare` takes the first two environments in `project.yaml`. The output is
Markdown, so you can paste it into a pull request. When either environment has
problems, it lists them instead and exits with `1`.

In VS Code, run **Ingestron: Compare environments**. With more than two
environments it asks which two.
