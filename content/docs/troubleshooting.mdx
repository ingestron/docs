---
title: "Troubleshooting"
description: "Start with the message or result you can see."
---

## npm reports EBADENGINE

Run `node --version` in the same terminal. CLI 0.15.0 and core 0.12.2 require Node
22.12 or newer. Earlier releases restricted the major version to 22. Install the
current documented CLI and check `ingestron --version`.

## npm cannot find a newly published version

Registry caches can take time to update. Retry after a few minutes. Do not republish
the same version or downgrade a project lock to work around a temporary lookup error.

## The shell cannot find ingestron

Open a new terminal after global installation. Check the npm global executable path
and the active Node installation. A Node version manager can change which global
packages are visible when you switch runtimes.

## A plugin name or version is unavailable

Check the name: the official provider is `local`; connectors are `github`, `files`,
`azure-blob` and `sql-server`. Use `provider install` for the former and
`connector install` for the latter with CLI 0.15.0 or newer.
For a catalogue lookup failure, retry or install the exact version shown in the
[tutorial](/docs/tutorials/github-to-parquet). A package in another repository needs
an explicit reference. Do not delete a working lock just to force a lookup.

## Python preparation fails

Check for Python 3.12 and pass `runtime prepare --python /path/to/python3.12`
if needed. Preparation needs internet access for locked packages. Keep the error
message but remove any private paths or credentials before sharing it.

## Discovery fails with authentication or rate limits

Check the repository name, token read permissions and organisation approval.
If GitHub is limiting requests, wait before retrying. A timeout is not proof that
no API calls were made. Keep the source small while testing setup.

## Review already exists or approval is stale

Keep the old files. [Build into a new directory](/docs/guides/update-project),
discover and review again, and use that directory consistently with `--from`.
Do not alter the approval record or generated digests.

## Retry rejects changed output

Preserve the affected output and receipt. Restore known original bytes if appropriate,
or create a new reviewed build and run. Editing `commit.json` cannot make changed
data a verified copy of the original snapshot.

## The contract draft would overwrite a file

This protects your existing contract. Review and edit it deliberately rather than
using repeated drafts as an update mechanism. Run `contract check` after edits.

## Get more detail

Use `--json` for structured diagnostics and `--verbose` for supported detailed views.
Include the command, package versions and a minimal redacted configuration when
reporting a problem in the [owning repository](https://github.com/ingestron).
Do not include `.env`, tokens, private issue titles or full data files.

## A documented plugin name is unknown

Run `ingestron --version`. The `files` name requires CLI 0.14.0 or newer;
`azure-blob` requires 0.14.1 or newer. Install the published CLI 0.15.0 or newer
for `sql-server` and the separate `provider` and `connector` commands.
An npm publication does not upgrade your installed command. Follow
[upgrade an existing installation](/docs/start/installation#upgrade-an-existing-installation)
and check for multiple Node installations if the version stays old.
