---
title: "Keep tokens out of your project files"
description: "Pass only declared credentials to a local source runtime."
---

Put the token in an untracked `.env` file. Put only its reference in project YAML:

```yaml
auth_token:
  $secret:
    env: INGESTRON_GITHUB_TOKEN
```

The matching file contains:

```dotenv
INGESTRON_GITHUB_TOKEN=replace_with_your_token
```

Add `.env`, `.ingestron/` and `build/` to `.gitignore` before creating credentials
or running a flow. Do not put tokens in command arguments, screenshots or Git.

## Use the secret file

```sh
ingestron run --action discover --secrets-file .env
ingestron run --run-id issues-001 --secrets-file .env
```

The path is relative to the project. The runtime receives declared secret names,
not every environment variable in the file. Use `--secrets-file`, not `--env-file`;
Node can interpret the latter before the CLI starts.

## Understand local execution

Python runs as your operating-system user. It is not a security sandbox. Runtime
preparation downloads dependencies and can execute upstream package build code.
Install packages you trust, review the project and use credentials with only the
access that source needs.

Logs and generated data can be sensitive even when the token itself is filtered.
Share redacted diagnostics and configuration, never the secret file or private
source rows. If a token leaks, revoke it at the source and replace the local value.
